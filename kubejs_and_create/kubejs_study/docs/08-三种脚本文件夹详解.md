# 08 - startup / server / client 三种脚本文件夹详解

## 一、机制层：源码里怎么定义的

### 三个路径常量（`KubeJSPaths.java:38-40`）

```
<游戏目录>/kubejs/startup_scripts/
<游戏目录>/kubejs/server_scripts/
<游戏目录>/kubejs/client_scripts/
```

另外还有一个较少人知道的本地目录 `kubejs/local/local_*_scripts/`（`KubeJSPaths.java:52-53`），
机制完全相同，用于放不想随整合包分发的个人脚本。

### 权威定义（`ScriptType.java` 的类注释，翻译）

> - **STARTUP**：在模组初始化时加载**一次**；重新加载需要**完整重启游戏**。用于注册内容和其它必须在世界加载前完成的修改。
> - **SERVER**：可通过 **`/reload`** 重新加载；用于配方、战利品表和服务器端事件。
> - **CLIENT**：可通过 **F3+T**（资源包重载）重新加载；用于 tooltip、渲染和客户端事件。

每种 ScriptType 还各自持有：
- 独立的 `ConsoleJS` —— 日志分别写到 `logs/kubejs/startup.log`、`server.log`、`client.log`，报错要看对应文件
- 独立的 `ClassFilter` —— 脚本能访问哪些 Java 类由 `kubejs.classfilter.txt` 白名单控制，**三种类型的白名单不同**（这也是为什么某些类只在 server 脚本里能用）

### 文件规则（`ScriptManager.collectScripts` + `ScriptFile.java`）

- 只加载 `.js` 和 `.ts` 文件（`.d.ts` 类型声明文件会被跳过）
- 子文件夹可以随便建，最深递归 10 层，对功能没有影响，只影响文件 ID
- **加载顺序**：先按文件头注释的 `priority` 降序，再按文件路径排序（`ScriptFile.java` 类注释）

### 文件头注释属性（`ScriptFile.java` 类注释）

在任何代码行之前写行注释即可控制该文件行为：

```js
// priority: 10        // 数字越大越先执行（默认 0）
// requires: create     // 只在装了 create 模组时加载，可写多个
// requires: client     // 只在客户端执行
// ignored: true        // 整个文件跳过（临时禁用脚本用这个，比删文件好）
// packmode: expert     // 只在指定整合包模式加载
```

### 事件可见性规则（`EventGroup.java` + `ScriptTypePredicate.java`）

事件在定义时声明了它属于哪种脚本类型，订阅错了会直接报错：

| 事件声明 | 在哪能订阅 | 源码依据 |
|----------|-----------|----------|
| `GROUP.startup(...)` | 仅 startup_scripts | |
| `GROUP.server(...)` | 仅 server_scripts | |
| `GROUP.client(...)` | 仅 client_scripts | |
| `GROUP.common(...)` | **server + client** 都行，startup 不行 | `COMMON = type != STARTUP`（`ScriptTypePredicate.java:10`） |

所以 `PlayerEvents.tick`、`BlockEvents.rightClicked`、`EntityEvents.death` 这些 common 事件，
在 server 和 client 脚本里都能写——但要不要写在那边，见第三节。

## 二、三个文件夹的职责对照

| | startup_scripts | server_scripts | client_scripts |
|---|---|---|---|
| **执行位置** | 游戏启动（模组初始化） | 内置/专用服务端 | 你的游戏客户端 |
| **生效范围** | 单机+所有玩家，全局 | 服务器权威，所有玩家 | 只有你自己看到 |
| **重载方式** | 改完必须**重启游戏** | `/reload` | F3+T |
| **可用事件** | 仅 startup 类 | server + common 类 | client + common 类 |
| **主事件组** | `StartupEvents` | `ServerEvents`、`PlayerEvents` | `ClientEvents`、`RecipeViewerEvents` |

注意一个常见误解：**单人游戏也有服务端**。`server_scripts` 在单人世界里同样运行，
所以改配方、写逻辑在单人环境就能测，不需要开专用服务器。

## 三、哪些功能放哪个文件夹（决策表）

### 放 startup_scripts（凡是"注册"都在这）

| 功能 | 事件 |
|------|------|
| 注册新物品/方块/流体/附魔/音效 | `StartupEvents.registry('item', ...)` 等 |
| 自定义创造模式物品栏 | `StartupEvents.modifyCreativeTab(...)` |
| 附属扩展的内容类型（如 Create 的砂纸、序装配列物品） | 同上，走 registry |
| 世界加载前必须确定的内容 | `StartupEvents.init/postInit` |

**判断标准**：这件事的结果要进**注册表**、且改完必须重启游戏才生效 → startup。
注册表在游戏启动后就冻结了，这就是 startup 不能热重载的根本原因。

### 放 server_scripts（凡是"游戏数据和逻辑"都在这）

| 功能 | 事件 |
|------|------|
| 增删改**配方** | `ServerEvents.recipes` |
| 改**标签** | `ServerEvents.tags` |
| 改**战利品表/掉落** | `BlockEvents.drops`（server 版）、`EntityEvents.drops`、战利品表事件 |
| 注册/处理**命令** | `ServerEvents.commandRegistry` / `command` |
| 服务器周期逻辑 | `ServerEvents.tick` |
| 玩家进出服、进度奖励 | `PlayerEvents.loggedIn` / `advancement` |
| 世界生成数据（矿脉、结构权重等） | `ServerEvents.generateData` |
| **方块/实体交互的游戏逻辑** | common 事件（`rightClicked`、`broken`、`death`…）写在 server 侧 |

**判断标准**：这件事应该对**所有玩家一致**、由服务器裁决 → server。

### 放 client_scripts（凡是"纯显示"都在这）

| 功能 | 事件 |
|------|------|
| JEI / REI / EMI 界面定制 | `RecipeViewerEvents.*` |
| 物品 tooltip 的**纯显示**修改 | client 版 tooltip 事件 |
| HUD、界面渲染 | `ClientEvents.*` |
| 自定义按键 | `KeyBindEvents.*` |

**判断标准**：只影响自己屏幕上显示什么 → client。
改错了顶多自己看到的不一样，不会影响别人，也不会被服务器修正。

### common 事件两边都能写，怎么选？

以 `BlockEvents.rightClicked` 为例：

- 右键触发**游戏效果**（给物品、改数据、爆炸）→ 写在 **server_scripts**，所有玩家一致
- 只想**弹个本地提示、播放仅自己可见的效果** → 写在 client_scripts

不确定就放 server：服务端逻辑是权威的，客户端逻辑在多人环境下随时可能和服务器状态对不上。

## 四、放错位置会怎样（常见报错现象）

| 症状 | 原因 |
|------|------|
| 在 startup 写 `ServerEvents.recipes` 报"事件不存在" | server 类事件对 startup 脚本不可见（见第一节可见性表） |
| 改了配方但没生效、也不报错 | 写到 client_scripts 去了——客户端改配方只骗过自己界面，服务器（包括单人内置服务端）不认 |
| 注册了物品，`/reload` 之后没出现 | 注册只能发生在 startup，必须**重启游戏** |
| 日志里找不到脚本报错 | 三种类型日志分开，看 `logs/kubejs/` 下对应文件 |
| 整合包其他人的脚本不跑 | 文件头没加 `requires: <模组id>`，或对方没装该模组 |

## 五、一图流记忆法

```
这东西要进"注册表"吗？ ──是──> startup_scripts   （改了要重启游戏）
        │否
这东西是纯显示吗？     ──是──> client_scripts     （F3+T 重载，只影响自己）
        │否
其他一切（数据/逻辑） ──────> server_scripts      （/reload 重载，对所有玩家生效）
```
