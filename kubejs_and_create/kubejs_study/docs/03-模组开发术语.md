# 03 - 模组开发术语（看源码必备）

遇到不懂的词先来这里查。按"是什么 → 在本项目哪里能看到"来写。

## Gradle / Gradle Wrapper

- **Gradle**：Java 项目的构建工具，负责下载依赖、编译、打包。`build.gradle`（或 `.kts`）就是它的配置文件，相当于前端的 `package.json`。
- **Gradle Wrapper**（`gradlew` / `gradlew.bat` + `gradle/wrapper/`）：自带固定版本 Gradle 的启动脚本，保证所有人用的构建工具版本一致。Windows 上用 `gradlew.bat`。
- `gradle.properties`：版本号等变量集中在这里，配置文件里用 `$变量名` 引用。
- `settings.gradle`：声明项目名、子模块、插件仓库。

## NeoForge / Forge

Minecraft Java 版的**模组加载器**。原版 MC 不支持模组，Forge/NeoForge 负责加载、兼容各个模组。较新的版本社区主推 NeoForge（kubejs 仓库 README 里的 `kubejs-neoforge` 就是它）。

## @Mod 注解

`@Mod("kubejs_create")` 标在主类上，告诉 NeoForge："游戏启动时实例化这个类，mod id 是 kubejs_create"。
对应元数据文件：`src/main/resources/META-INF/neoforge.mods.toml`（模组的名片：id、版本、依赖）。

看 `KubeJSCreate.java` 会发现它是个**空类**——真正干活的是 `KubeJSCreatePlugin`（见 02 文档），主类只是让加载器有个挂载点。

## Mixin（混入）

Mixin 是一种**运行时注入技术**：不改别人的 jar 文件，而是在类加载时把代码"混入"目标类，用来修改原版/其他模组的行为。

- 代码在 `core/mixin/` 包，如 `ProcessingOutputMixin`
- 配置在 `src/main/resources/*.mixins.json`（列出有哪些混入类）
- `kubejs.classfilter.txt`：限制混入/访问范围的过滤文件

看 mixin 类时的要点：`@Mixin(目标类.class)` 声明混入谁，`@Inject` / `@Redirect` 等注解说"在目标方法的什么时机插入代码"。KubeJS-Create 里 `ProcessingOutput` 的 mixin 被作者自嘲为 "mildly cursed"（ mildly 咒术）——说明这是比较 hack 的写法。

## Access Transformer（AT）

`META-INF/accesstransformer.cfg`：把别人 jar 里的 private/protected 成员**改成 public** 的清单。和 Mixin 的区别：AT 只改访问权限，Mixin 能改逻辑。

## 注册表（Registry）与 ResourceLocation

- Minecraft 里所有内容（方块、物品、流体、配方类型……）都在启动时**注册**到一个全局注册表，之后不能改。
- `ResourceLocation`（新版叫 `Identifier` 概念相同）：`命名空间:路径` 格式的全局唯一 ID，如 `create:crushing`。脚本里的 `'minecraft:sand'` 就是它。
- 源码里 `Registries.ITEM`、`Create.asResource(...)` 都跟这有关。

## Data Component（数据组件，1.20.5+）

物品附带数据的新机制，取代了老的 NBT。比如物品的耐久、附魔都是 data component。
`registerDataComponentTypeDescriptions` 这个方法就是在告诉 JS 侧"Create 的这些组件是什么类型"，方便脚本补全。

## Codec

Minecraft 官方的**序列化框架**：定义"Java 对象 ↔ JSON"怎么互转。配方从 JSON 加载、存档数据读写都用它。看到 `Codec`、`StreamCodec` 就是这一类。

## Datapack（数据包）与 resources 目录

`src/main/resources/data/...` 就是模组内置的数据包：配方、战利品表、进度等 JSON 都放这里，路径规则和数据包完全一样。KubeJS 脚本生成的配方最终也是走这条管线。

## Mojmap / 反混淆

Minecraft 正式版代码是混淆过的，社区用一套统一映射（Mojmap，官方映射名）还原可读类名。所以源码里类名如 `net.minecraft.world.item.ItemStack` 是映射后的名字。开发模组前 Gradle 会自动做这一步（`...deobf...` 任务）。

## 附属模组（Addon）

基于某个模组的 API 再开发一层功能的模组，依赖"宿主"才能运行。依赖关系在这里是：

```
Minecraft + NeoForge
        └── Create（机械动力）
        └── KubeJS
                └── KubeJS-Create（同时依赖上面两个）
```

在 `build.gradle` 的 `dependencies` 里能看到这些依赖声明（maven 仓库 `maven.latvian.dev` 提供 KubeJS 的 jar）。
