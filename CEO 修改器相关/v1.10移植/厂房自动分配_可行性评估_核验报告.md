### 3.2 §6.4 "`4A8C24` 无任何指令引用" —— 搜索错误，结论要推翻

文档搜的字节串是 `24 8C 4A 00`（把 CE 记法里的 **RVA** 当成 VA 直接搜了）。
正确做法：CE 里 `CEO.exe+X` 的 X 是 RVA，IDA 里的 VA = 0x400000 + RVA，所以该全局 VA = **0x8A8C24**，文件内字节序应是 `24 8C 8A 00`。

实测（对 `D:\gameapp\...\CEO.exe` 全文件检索）：

| 搜索串 | 命中 |
|---|---|
| `24 8C 4A 00`（文档搜法=RVA） | **0** |
| `24 8C 8A 00`（正确=VA 0x8A8C24） | **18** |

且反汇编侧有 **8 个函数**引用 `dword_8A8C24`：`418880 / 4189A0 / 418AC0 / 40A6B0 / 43DBA0 / 419580 / 4196B0 / 4450F0`。

**后果**：§6.4 的"自动分配不要依赖 4A8C24"这条警告作废；主表 Ctrl+Z/X 无隐患。
**教训（建议补进实战记录坑点）**：本项目存在"CE 记法(RVA) / IDA 记法(VA)"两套地址体系，跨工具检索时必须换算，否则会得出"该地址无引用"的错误结论。

### 3.3 §5.3 伪代码的调用目标错误 —— 照做会失败

文档 §5.3 让人调用：
```
调 CEO.exe+185E0(厂房号, t.下标, t.中心X, t.中心Y)   // 放主管
调 CEO.exe+18730(厂房号, t.下标, t.中心X, t.中心Y)   // 放工人
```
但真实代码里这两个函数的 `a2`（下标）是**表B（类别0 厂房本体容器）的下标**，按 `dword_4D0C84 + a2 * dword_4D0C70` 寻址，写的是 `表B[+0x18...]` 槽、人员记录 `+0x1A`。**把机器工位下标传进去 = 往随机的表B记录放人**（本节开头举例的 4185E0 编制检查、表B下标寻址见下方代码）。

**工人→机器的正确函数是 `CEO.exe+18330`（`sub_418330`）**：

```c
int sub_418330(int a1/*厂房号*/, int a2/*表A工位下标*/, int a3/*x*/, int a4/*y*/)
{
  if ( 厂房[+0x1D2] - 厂房[+0x1D6] <= 0 ) return 0;      // 工人编制余量检查
  v5 = dword_8703D0 + a2 * dword_8703BC;                  // ← 表A 寻址（机器工位）
  if ( sub_431030(v5) >= 4 ) return 0;                    // 该工位 4 个工人槽已满
  ... 多轮散布重试 ...
      v6 = sub_42BD50(a1, 0/*工人*/, x, y, rand&3, 0);
  for ( i = v5 + 16; *i != 0xFFFF; ++i )                  // ← 找 +0x10..+0x16 里的空槽
      if ( ++v13 >= 4 ) return 0;
  *(_WORD *)(v5 + 2 * v13 + 16) = v6;                     // 写入槽位
  人员记录(v6)[14] = a2;                                   // 人员 +0x1C = 表A工位下标
```

**判据来源**：分派函数 `sub_418880`（点厂房落格的处理）——

## 4. 可行性判定：可以实现 —— 而且游戏自己有现成范例

### 4.1 决定性证据：游戏自带"自动配人"逻辑

**① `sub_403A50`（AI 工厂自动配人，就是用户想要的流程）**
```c
// 主管：遍历 表B 链，编制有余量且 目标>当前 就放
if ((*(_BYTE*)(表B记录 + 18) & 1) != 0) {
    if ( 厂房[+0x1D0] - 厂房[+0x1D4] > 0 ) {
        if ( 表B[+0x16]/*当前主管*/ < 表B[+0x14]/*目标*/ ) {
            sub_426BF0(&x, &y);                 // 取容器坐标
            sub_4185E0(厂房号, 表B下标, x, y);   // 放主管
        }
    }
}
// 工人上机器：遍历 表A 工位，空槽就放
for (v30 = 0; v30 < 工位数; ++v30) {
    if ( sub_431030(表A + v30*步长) == 0 ) {    // 该工位没工人
        sub_430CA0(&x, &y);                     // 取机器坐标
        sub_418330(厂房号, v30, x, y);          // 放工人到机器 ← 正是我们要做的
    }
}
// 工人到厂房：另一条链，目标>当前 就 sub_418730
```

**② `sub_45A8D0`（游戏 UI 的"一键配人"按钮）**
```c
for (i = 厂房[+0x2F0]; i != -1; i = 表B记录[+0x06]) {     // 遍历厂房容器链
    表B = dword_4D0C84 + i * dword_4D0C70;
    sub_426BF0(表B, &x, &y);
    if ( 表B[+0x14]/*目标主管*/ > 表B[+0x16]/*当前*/ ) {
        do { ++厂房[+0x1D0];                               // ★ 自动抬高主管编制上限
             厂房[+0x1C4] += 招聘成本;
             sub_4185E0(厂房号, i, x, y);
        } while ( 表B[+0x14] > 表B[+0x16] );
    }
    for ( ; 表B[+0x15]/*目标工人*/ > 表B[+0x17]/*当前*/; ) {
        ++厂房[+0x1D2];                                    // ★ 自动抬高工人编制上限
        厂房[+0x1C8] += 招聘成本;
        sub_418730(厂房号, i, x, y);

```

**含义**：路线 B 不是"绕过游戏"，而是**复用游戏自己的合法路径**；连"编制不够怎么办"游戏都给了答案（抬上限 + 扣招聘成本）。文档对风险的判断（盲写崩溃）因此可以完全规避。

### 4.2 文档没写、但实现必需的三点

1. **放人前必须保证编制余量**：`4185E0/418330/418730` 开头都是 `if (上限 - 在岗 <= 0) return 0;`。若机器的编制上限没配够，直接调用永远返回 0。要么先 `++厂房[+0x1D0]/[+0x1D2]`（照抄 45A8D0），要么依赖游戏已给的编制。
2. **必须传坐标**：`a3/a4` 不是可有可无——`sub_42BD50` 里用它们做落点校验（`sub_42BC50`）决定"空格或机器空位"。坐标应像游戏那样取：容器坐标 `sub_426BF0(表B记录, &x, &y)`；机器坐标 `sub_430CA0(&x, &y)`。
3. **调用后刷新界面**：分派函数成功后会调 `sub_427A10(表B记录)` 或 `sub_444AB0()`；直接调底层函数时同样要补这一步，否则面板数字不更新（文档 §5.3 第 4 步提了"待定位"，现已定位）。

### 4.3 建议的落地顺序（修订版）

1. ~~建 1.10 IDA 库~~ → **跳过**（已具备）
2. **单点验证**：`ce_call_function("CEO.exe+18330", [厂房号, 表A工位下标, x, y])` 放 1 个工人到 1 台机器 → 看面板 `m/n` 是否 +1。

4. **批量**：遍历该厂房所有机器工位，逐台补满（照抄 sub_403A50 第二段）

## 5. 未解问题：主管如何上机器（需一次实测确认）

- 分派函数对**机器（类别6）只接受工人**（`8A8C24 == 2`）；三个放人函数里只有 `418330` 写 表A；**未找到"主管→机器"的代码路径**。
- 但机器面板确实显示 `0/1`（4 台机器各需 1 个主管），说明主管最终要落到机器上。
- 线索：**表A 记录其实有两组各 4 个 word 槽**——`+0x08..+0x0E` 与 `+0x10..+0x16`；`418330`（工人）写的是 **+0x10 组**，`sub_431030`/`sub_430F50` 也只统计 +0x10 组。**+0x08 组很可能是主管槽，但未找到写入者**（可能是生产作业/自动机制，或机器实例侧另有记录）。

**两分钟可验证的实验**（同时校验我们对分派逻辑的理解）：
1. 开 Ctrl+Z（8A8C24=1 主管模式）→ 点一台机器 → 按代码预测：**不会**发生任何事（因为 case 6 要求 ==2）；
2. 同一个"主管按到机器上"的操作，观察面板 `x/y` 是否变化；
3. 若确认不能手动放，则主管只能停在厂房容器（表B）——此时需要重新确认面板第一对数字的来源（可能来自 `Machine_type.csv` 的 `管理人數` 与厂房级主管的映射）。
