## 二、★ 游戏内置作弊控制台（本项目最重要的发现）

### 2.1 怎么用

- **打开**：按住**左 Ctrl** 再按 **F5**；**关闭**：**ESC**
- 出现一个输入框，输入命令后回车

### 2.2 完整命令表（已穷尽确认，全游戏仅此 7 条）

| 命令 | 作用 | 内部实现 | 实测 |
|---|---|---|---|
| `wkrfill` | **把当前厂房每个岗位按需求配满（主管+工人）**，自动抬编制、扣招聘费 | `sub_45A8D0` | ✅ |
| `buildok` | 当前选中物件一键完工 | `sub_45A730(dword_4B1024)` | ✅ |
| `buildokall` | 全部建造完工 | `sub_45A8B0` | ⬜ 范围未实测 |
| `money` | 所有公司 +1 亿 | `sub_42EDA0` | ⬜ |
| `money1` | 本公司 +1 亿 | `sub_42EDA0` | ⬜ |
| `talk` / `notalk` | 开启 / 关闭对话（调试用） | 写 `dword_8CAF70` | ✅ |

**穷尽性依据**：① 全量反编译源码提取所有 `strcmp` 字面量，命令型仅这 7 个（另一个 `go` 是对话框逻辑）；② 命令分发表所在界面 `face_cheat.fce` 只含一个控件（`face_cheat.h` 枚举仅 `EDIT_CHEAT`）；③ 文本输入缓冲 `dword_8CB0A0` **全游戏仅被该分发器引用** → 不存在第二处命令入口。

### 2.3 自动化调用方案（已实现进主表 F6~F10）

**不调用任何游戏函数**，走"按键 + 窗口消息"，因此**零崩溃风险、且不要求游戏在前台**：

```lua
-- ① 打开控制台：左Ctrl 用 keybd_event 设"真实键状态"（骗过游戏的 GetAsyncKeyState 判定）
executeCodeEx(0, nil, getAddress('keybd_event'), 0xA2, 0x1D, 0, 0)   -- 左Ctrl 按下
SendMessage(hwnd, 0x100, 0x74, 0x003F0001)                            -- WM_KEYDOWN F5
SendMessage(hwnd, 0x101, 0x74, 0xC03F0001)                            -- WM_KEYUP   F5
executeCodeEx(0, nil, getAddress('keybd_event'), 0xA2, 0x1D, 2, 0)   -- 左Ctrl 抬起
-- ② 逐字输入命令（WM_CHAR，50ms 间隔）
SendMessage(hwnd, 0x102, string.byte(ch), 1)
-- ③ 回车执行（控制台自动关闭）
SendMessage(hwnd, 0x100, 0x0D, 0x001C0001)
SendMessage(hwnd, 0x101, 0x0D, 0xC01C0001)
```

**执行前校验**：读 `CEO.exe+4CAF74`（控制台"已创建"标志，创建时 `mov dword [0x8caf74],1`）——未打开就不输入，避免把命令文字误打进游戏。

## 三、已恢复的内存结构知识（可复用于后续功能）

### 3.1 地图对象（地图上的地块与建筑）

元素地址 = `[CEO.exe+C43DC] + [CEO.exe+C43C8] × [CEO.exe+B1024]`（选中基址/步长/编号三全局）

| 偏移 | 含义 |
|---|---|
| +0 | word 对象 ID |
| +2 | byte FF=无建筑地块 / 00=有建筑 |
| +3 | byte 建筑类型（2=居民楼，3=矿场） |
| **+4** | byte **矿物种类**（0-9，255=无矿） |
| **+6** | byte **矿品质** |
| **+8** | dword **矿储量** |
| +18 | dword FFFFFFFF = 无主标记 |

### 3.2 厂房结构（`[CEO.exe+CCAAC] + 厂房号 × [CEO.exe+CCA98]`）

| 偏移 | 含义 |
|---|---|
| +0x18 / +0x1C | 格宽 / 格高（实测 22 × 22） |
| +0x8C | 格表指针（格 → 物件下标，-1=空） |
| +0xA0 / +0xB4 | 物件记录步长(24) / 物件数组基址 |
| **+0x1D0 / +0x1D2** | **主管 / 工人编制上限**（招聘时逐次 +1） |
| **+0x1D4 / +0x1D6** | **在岗主管 / 在岗工人** |
| +0x2F0 | 表B（用工岗位）链头 |
| +0x2F6 | 表A（机器工位）链头 |
| +0x320 + 类别×2 | 按类别的可用池计数 |

### 3.3 表B = 每台机器一条"用工岗位"记录（`[CEO.exe+D0C84] + 下标 × [CEO.exe+D0C70]`）

**机器面板显示的 `x/y m/n` 就是这条记录的字段**：

| 偏移 | 含义 | 对应面板 |
|---|---|---|
| +0x02 | word 厂房号 | — |
| +0x06 | word 链 next（-1=链尾） | — |
| +0x10 | word 关联物件下标 | — |
| +0x14 / +0x15 | byte 主管 / 工人**需求** | y / n |
| +0x16 / +0x17 | byte 主管 / 工人**当前** | x / m |
| +0x18 起 | 20 个 word 主管槽（空=FFFF） | — |
| +0x40 起 | 20 个 word 工人槽 | — |

### 3.4 其他

- **人员记录**：`[CEO.exe+D10A8] + 序号 × [CEO.exe+D1094]`（**步长 40**）；+0x0B 类型位（低4位 0=工人 1=主管）、+0x0E 厂房号、**+0x1A 所属表B岗位下标**、+0x1C 表A下标、+0x1E 类别7
- **物件记录**：步长 24；+0x0B 类别、+0x0C 关联下标（表B 或 表A）
- **表A**：`[CEO.exe+4703D0] + 下标 × [CEO.exe+4703BC]`，类别6=机器工位，+0x10..+0x16 四个工人槽、+0x1C 空位标记、+0x1F 类别
- **机器类型表**：`[CEO.exe+470824] + 类别 × 112`（需求值来源，对应 `data\Machine_type.csv` 的 管理人數/工人數）
- **携带描述符表**：`[CEO.exe+D10B0]`，8 字节/条（+0 物件ID、+2 类型、+3 阈值）；比较值 `CEO.exe+4CD128`
- **控制台**：标志 `CEO.exe+4CAF74`、文本缓冲对象 `[CEO.exe+4CB0A0]+0x28`

### 3.5 文本与编码（2026-09-15 全量提取时确定）

- **界面主语言 = 繁体中文，编码 = Big5（大五碼）**。做文本替换/本地化改 **Big5 字节**，不要动 UTF-16。
- **`CEO.exe` 里有真实 Big5 中文（92 条）**，位于 **`.rdata`（73 条，RVA ≈ `0xA2000`–`0xB0C0C`）** 与
  **`.data`（18 条，RVA ≈ `0xB1000`+，关卡名/地图名/`細明體`）**：教学文本、关卡名（`教學關卡一`～`六`）、
  地图名（`加勒比海`/`北京市`/`北美洲`）、UI 标签（`產品名稱`/`原始需求`/`總零售利潤`/`學生人口`…）、报错串（`的參數數量不對`/`機器入口座標錯誤`）。
  → 查 UI 文本/报错来源时可直接在 exe 里检索，不必只依赖 CSV。
- **UTF-16LE 只有 Steam 包装层的 34 条**（月份/星期/`800 x 600`/`Windows原設定`），**无游戏本体文本**。
- **APKG 索引格式**：`'APKG'` + `u32 索引起始偏移` + `u32 文件数`；索引每条 40 字节 = 文件名(32, Big5) + 偏移(u32) + 大小(u32)。
- **`.stg` 格式**：`重复{ u32 段号 + u32 压缩长度 + zlib 流 }`。
- 全量产物见 `..\v1.10反汇编资源\06_字符串提取\`（去重 10,836 条，含中文 1,943 条）。
  ⚠️ 该目录 TSV 里的地址是 **RVA**（`CEO.exe+偏移`），换算 `VA = 0x400000 + RVA`。

## 五、踩过的坑（#1-#18 索引，详见实战记录）

| 编号 | 一句话 |
|---|---|
| #1 | **进程基址每次启动都变** → 一律 `CEO.exe+RVA`，禁止绝对 VA |
| #2 | CE AA 不支持 `h` 后缀十六进制（`4D10B8h` ×） |
| #3 | CT 是 XML，注释里不能有裸 `<`/`&` |
| #4 | F2 绑在脚本条目上 = 切换脚本启停，不是翻转内存标志 |
| #5 | 换脚本前必须卸载旧钩子或重启游戏 |
| #6 | MCP 的 `ce_auto_assemble` 偶发失败 → 走 `ce_execute_lua(pcall(autoAssemble,...))` |
| #7 | `ce_find_what_writes` 有监控窗口时序问题 → 改用常驻硬件断点 |
| #8 | 游戏重启后 MCP 需重新附加、CT 脚本需重新勾选 |
| #9 | 空地"造矿"盲写会闪退（走原生路径） |
| #10 | 别假设相关全局在内存里相邻 |
| #11 | CE 组合键热键可能与游戏内置快捷键冲突（Ctrl+C 已踩） |
| **#12** | **RVA/VA 混用会得出完全错误的结论**（CE 用 RVA，反汇编用 VA，`VA = 0x400000 + RVA`） |
| **#13** | **直接调用游戏函数前必须核对调用约定**（`426BF0` 是 thiscall，按 cdecl 调 → 崩） |
| **#14** | **无参 cdecl 函数也会崩**——CE 调函数是在目标进程新建线程，单线程游戏从外部线程碰 UI/游戏逻辑极易崩 |
| **#15** | **二进制里裸扫 Big5 = 海量假阳性**（机码凑巧双字节可解码）→ 必须用「游戏用字集」过滤 |
| **#16** | 写 TSV 前须转义 `\t`/`\r`/`\n`（exe 的 ASCII 串允许含制表符，实测 103 条） |
| **#17** | `.stg` 是多段 zlib 拼接，不能整文件 `zlib.decompress`（报 `incorrect header check`） |
| **#18** | **文件偏移 ≠ RVA**——PE 节 `RawPtr ≠ VirtAddr`（`.text` `0x400`/`0x1000`），跨"文件↔内存"的地址必须先按节表换算，并用独立来源交叉验证 |

## 七、接下来的路线

### 阶段 A：收尾与验证（低成本，建议先做）

3. 探明品质/储量上限，如需"拉满"功能补一条参数条目。

### 阶段 B：需要你决策的技术升级

4. **主线程派发（AA 钩子 + 命令队列）**——在游戏自己的线程里调用函数，可实现"无控制台闪烁"的直调版本（含直接把 `wkrfill`/`418730` 调起来）；工作量约 1~2 小时含调试，期间有崩风险（需多存档）。**收益是更干净，不是多功能**。

### 阶段 C：剩余功能开发（各需一轮"规格→定位→验证"）

5. **机器秒生产**：v1.02 参照 `s08/s09`（钩 0x42790F/0x427765，生产计数 +1 / 写 800000）；1.10 被重写，需重新定位生产推进代码；

### 阶段 D：工程化收尾

8. 打包为独立修改器（可复用 `loader_v110.py` 骨架）；
