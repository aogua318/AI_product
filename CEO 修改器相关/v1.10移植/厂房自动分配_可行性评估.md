## 3. 已恢复的工厂/机器逻辑（v1.02 语义，1.10 同构）

### 3.1 完整放置链路

**第 1 步 拾取人员**（v1.02 `sub_4192F0`）：

```c
记录 = 人员记录数组[dword_497E84];              // 497E84 = 被点中的人
类型位 = 记录[+0x0B] & 0x0F;                     // 0=工人 1=主管 2=不可拾取
if (记录[+0x1A] != -1)      { 49798C = 0; 497990 = 记录[+0x1A]; }   // 归属：类别0容器
else if (记录[+0x1C] != -1) { 49798C = 6; 497990 = 记录[+0x1C]; }   // 归属：类别6 = 机器
else if (记录[+0x1E] != -1) { 49798C = 7; 497990 = 记录[+0x1E]; }   // 归属：类别7
放置人模式全局 dword_88EFDC = 1;                 // 1=主管 2=工人
```

**第 2 步 点击落格（分派）**（v1.02 `sub_40A180`）：

```c
if (dword_88EFDC) {                              // 处于"放人"模式
    容器类别 = dword_49798C; 容器下标 = dword_497990;
    dword_4B2D14 = 容器类别;  dword_4B2B58 = 容器下标;
    屏幕坐标 -> 格子坐标(sub_42FE10 / sub_433760 / sub_4265B0 按类别不同);
    sub_4191D0(x, y);
    dword_88EFDC = 0;                            // 放完即退出模式
}
```

**第 3 步 分派到四种放法**（v1.02 `sub_4191D0`，`switch (dword_4B2D14)`）：

| 模式 | 调用 | 目标容器 | 用途 |
|---|---|---|---|
| 0 | `sub_418EF0(厂房号, 下标, x, y)` | 表 B | 放主管（主管槽从 +0x18 起，计数 +0x16，上限 20） |
| 0 | `sub_419060(厂房号, 下标, x, y)` | 表 B | 放工人（工人槽从 +0x40 起，计数 +0x17，上限 20） |
| 6 / 9 | `sub_418C30(厂房号, 下标, x, y)` | **表 A** | 放进"类别 6 = 机器"记录（4 个工人槽 +0x10..+0x16） |
| 7 | `sub_418DA0(厂房号, 下标, x, y)` | 表 C | 类别 7 容器（单槽 +0x0C） |

四个函数体几乎一致：

```c
if (厂房[+0x1D0] - 厂房[+0x1D4] <= 0) return 0;   // 主管编制检查（工人版 +0x1D2 - +0x1D6）
记录 = 表基址 + 下标 * 表步长;
if (记录计数 >= 20 或工位已满) return 0;
do {                                              // 多轮重试，每轮扩大散布范围
   x = 目标x + rand()%n - rand()%m;  y = 目标y + rand()%n - rand()%m;
   人 = sub_42AA80(厂房号, 类型(0工人/1主管), x, y, rand()&3, 0);
} while (人 == -1 && 还能重试);
记录.槽位[空位] = 人;  人员记录[归属字段] = 下标;  记录.计数++;
```

**第 4 步 生成人**（v1.02 `sub_42AA80`，1.10 `CEO.exe+2BD50`）：

```c
if (!sub_42A960(厂房号, x, y)) return -1;         // 落点合法性
句柄 = sub_482240(携带描述符[0], x, y, ...);       // 在地图上建人
记录[+0x10] = 句柄;  记录[+0x0B] 更新类型位;

记录[+0x0E] = 厂房号;  记录[+0x04]/[+0x06] 挂进 厂房[+0x2FC] 人员链
```

### 3.2 "点机器才算分配"的判定（v1.02 `sub_42A960`，1.10 `CEO.exe+42BC50`）

```c
厂房 = 厂房数组[厂房号];
格内物件 = 厂房[+0x8C][ x + y * 厂房[+0x18] ];
if (格内物件 == -1) return 1;                       // 空格：允许（但不进机器）
物件 = 厂房[+0xB4] + 格内物件 * 厂房[+0xA0];
if (物件[+0x0B] == 6)                               // 6 = 机器
    if (表A[ 物件[+0x0C] ][+0x1C] == 0xFFFF) return 1;   // 该机器记录有空位
return 0;
```

这就是"放空地不算分配、必须点到机器上"的代码答案：**合法目标 = 空格，或"类型=6（机器）且该机器记录还有空位"**。

### 3.3 为什么"机器槽位"找不到计数器

面板例程（v1.02 `sub_43B4F0` + 回调 `sub_43B660`）是**遍历人员记录现算**的：

`人员[+0x06]`（或 `+0x04`）= 厂房号 -> `人员[+0x10]`（byte）= 机器序号 -> `厂房[+0xF0 + 序号*2]` 得机器 -> 机器 `[+0x4E9]` 类别与当前选中类别比较 -> 计数（总数 / `[+0x13] & 0x10` 时另计"在岗"）-> `sprintf("%d/%d")`。

**机器侧没有计数器**；真正的"分配"写在人员记录与工位记录的槽位数组里。这也解释了侦查记录里"机器的槽位计数没有简单字节计数器"的现象。

### 3.5 厂房结构字段（1.10 同偏移，已用 0x185F5 / 0x18745 处代码复核）

| 偏移 | 含义 |
|---|---|
| +0x18 / +0x1C | 宽 / 高（格数） |
| +0x8C | 格 -> 物件下标 的二维表指针 |
| +0xA0 | 物件记录步长 |
| +0xB4 | 物件数组基址（`[+0x0B]`=类别，6=机器；`[+0x0C]`=表 A 下标） |
| +0xEE / +0xF0 | 按序号/类别的机器链头数组（word） |
| +0x2F2 / +0x2F6 | 表 A 工位链链头（`sub_4158F0` 按类别找可用工位） |
| +0x2FC | 厂房内人员记录链头 |
| +0x320（类别×2） | 按类别的可用池计数 |
| **+0x1D0 / +0x1D2** | **主管 / 工人「编制上限」**（放置前减在岗数） |
| +0x1D4 / +0x1D6 | 在岗主管 / 在岗工人（放置 +1、移除 -1） |
| +0x0E2 | 类型 2 计数 |
| +0xE0 | 与 `dword_856610` 比较的状态值 |

### 3.6 表 A / 表 B / 人员记录字段

**表 A 记录（类别 6 = 机器工位）**

| 偏移 | 含义 |
|---|---|
| +0x00 | 厂房号 |
| +0x04 | 链 next（同厂房同类别工位链） |
| +0x10..+0x16 | **4 个工人槽**（word，0xFFFF=空） |
| +0x1C | 落点校验要求的字段（==0xFFFF 才允许往这台机器放人） |
| +0x1F | 类别字节（与 机器实例 `[+0x4E9]` 比较） |
| +0x20 | 另一条链的 next |

**表 B 记录（类别 0 容器）**：`+0x16` byte = 主管数（槽数组从 `+0x18` 起，上限 20）；`+0x17` byte = 工人数（槽数组从 `+0x40` 起，上限 20）。

**人员记录**

| 偏移 | 含义 |
|---|---|
| +0x04 / +0x06 | 链表前后（厂房人员链，头在 厂房+0x2FC） |
| +0x0B | 状态 + 类型位（低 4 位：0=工人 1=主管 2=特殊） |
| +0x0C / +0x0D | 状态字节 |
| +0x0E | 厂房号 |
| +0x10 | 地图句柄（`sub_482240` 返回） |
| +0x14 起若干 dword | 位置/工位参数（`sub_42AC60` 写入） |
| **+0x1A** | 所属"类别 0 容器"下标 |
| **+0x1C** | **所属"类别 6 = 机器"记录下标** |
| **+0x1E** | 所属"类别 7"容器下标 |

### 3.7 "工厂里有哪些机器"——三种枚举方式

1. **扫表 A**：遍历表 A 全部记录，取 `[+0x00] == 目标厂房号` 的记录；`[+0x1F]` 是类别，`[+0x10..+0x16]` 是工人槽。
2. **走厂房工位链**：`厂房+0x2F6` 链头，沿 `记录+0x04` 走（`sub_4158F0`/`sub_4300C0` 就是这样找"同类别还有空位的机器"）。
3. **走机器实例链**：`厂房+0xEE+序号*2` -> 机器实例数组 -> 沿实例 `+0x06` 走，读 `+0x4E9` 拿类别；机器在厂内的格子可由厂房格表反查。

## 5. 实现路线与推荐做法

### 5.1 三条路线

| 路线 | 做法 | 风险 | 评价 |
|---|---|---|---|
| A 数据直写 | 直接改人员记录归属字段 / 工位记录槽位 | 字段一致性由游戏维护，盲写极易崩（参考"空地造矿闪退"） | 只用于验证结构，不用于交付 |
| **B 调游戏原生放置函数**（推荐） | 对每台机器调 `CEO.exe+185E0`（主管）/ `+18730`（工人），传（厂房号, 工位下标, 机器中心 x, y） | 参数要对；直接调用会跳过 UI 刷新 | 与手动点击同路径，合法性由游戏判定 |
| C 模拟点击 | 固定相机 + 标定坐标 + 模拟鼠标 | 相机一动就失效 | 备选 |

旁证：游戏自己就有"程序化放人"的代码——v1.02 `sub_418C30`/`sub_418EF0`/`sub_419060` 就是被 UI 与生产逻辑直接调用的；`sub_4128A0`（生产推进）也会调 `sub_42AC60 -> sub_42AA80` 生成作业工人。

### 5.2 自动分配的判据（关键）

`厂房[+0x1D0] - 厂房[+0x1D4]` = 还缺几个主管；`厂房[+0x1D2] - 厂房[+0x1D6]` = 还缺几个工人。
这两个"编制上限"应等于该厂房**所有机器需求之和**（需求来自 `Machine_type.csv` 的 管理人數 / 工人數）。

### 5.3 伪代码

```
厂房号 = 当前厂房
// 1) 枚举该厂机器工位（§3.7 任选一种）
工位列表 = 扫表A(厂房号) 或 走 厂房+0x2F6 链

// 2) 补主管
while 厂房[+0x1D4] < 厂房[+0x1D0]:
    t = 取一个"同类别且主管位未占用"的工位
    调 CEO.exe+185E0(厂房号, t.下标, t.中心X, t.中心Y)

// 3) 补工人
while 厂房[+0x1D6] < 厂房[+0x1D2]:
    t = 取一个"工人槽有空位"的工位
    调 CEO.exe+18730(厂房号, t.下标, t.中心X, t.中心Y)

// 4) 刷新界面（直接调上面两个函数时可能需要）
调 1.10 对应 sub_426460 + sub_4437C0（待定位）
```

先做**单台机器单点**验证（UI 的 `x/y m/n` 是否同步），再考虑批量；批量放 Lua 定时器/热键，最后并入主表 `v1.10CE数据\CEO_v1.10_主表.ct`。

## 6. 待验证清单

### 6.1 编制上限（最有价值）

读当前厂房 `[+0x1D0]` / `[+0x1D2]`。按侦查记录里那 7 台机器（3 台重型採礦機 0管/3工 + 4 台 1管/2工），**期望读到 主管=4、工人=17**。吻合则"编制上限 = 机器需求合计"成立，自动分配判据即可用。

### 6.2 归属字段写向

手动把 1 个工人放到某台机器上，前后比对：人员记录 `+0x1A/+0x1C/+0x1E` 与 表 A 记录 `+0x10..+0x16`。

### 6.3 人员记录步长

读 `CEO.exe+4D1094`，**预期 0x488**（与侦查记录"两次放置对象地址相差 0x488"吻合）。

### 6.4 疑点：`CEO.exe+4A8C24` 到底是不是游戏读的变量

- 1.10 整个文件里**搜不到任何指令引用它**（字节串 `24 8C 4A 00` 全文件 0 命中）；
- v1.02 里对应的"放人模式"全局 `dword_88EFDC` 却是被代码大量引用的（`sub_40A180`、`sub_4192F0`、`sub_4191D0` 都读它）。

含义：`4A8C24` 很可能不是游戏自己读的那个变量（可能只是凑巧触发了行为），1.10 真正对应 `88EFDC` 的全局**尚未定位**。
对策：建库后先在 1.10 里找 `sub_4192F0` / `sub_40A180` 的孪生函数，看它们写/读的是哪个全局；**在那之前，自动分配不要依赖 `4A8C24`**。
