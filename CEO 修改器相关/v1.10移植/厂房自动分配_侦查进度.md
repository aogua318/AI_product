## 1. 任务目标

给当前厂房里的所有机器**自动分配工人与主管**，替代手动"拾取→点到机器"的重复操作。

游戏内背景知识（用户确认）：
- 厂房视图（与 Ctrl+Z/X 使用的同一视图）里可放置机器和工人；
- 工人槽位格式 **x/y m/n**：x=当前主管数, y=主管需求, m=当前工人数, n=工人需求；
- 工人放到厂房空地不算分配，**必须点到机器上**才算分配到机器；
- 本厂 7 台机器：3 台"0/0 0/3"（重型采矿机）+ 4 台"0/1 0/2"（加工机/木工机/烧窑机×2）；
- 机器类型有：重型采矿机、重型加工机、重型木工机、重型烧窑机（不同类型 = 不同 machine type）。

实现路线决议：先走**路线 1（数据直写）**侦查；路线 2（模拟点击 mouse_event）作为备选。

## 2. 已实锤的发现（全部有断点/实测证据）

### 2.1 进入厂房视图 → 选中机制自动指向厂房

进入厂房后，阶段 2 的选中三全局（`CEO.exe+B1024` 编号 / `+C43C8` 步长 / `+C43DC` 基址）直接指向当前厂房的**地图对象元素**，其 +4/+6/+8（矿种/品质/储量）与厂房侧栏显示一致。
**因此"当前厂房"可以随时定位**：`elem = [C43DC] + [C43C8] × [B1024]`。

### 2.2 厂房结构（本次侦查 RDI=0x1761450，⚠️ 地址随进程/存档变化，方法可复现）

通过"在工人数计数器挂硬件写断点 + 放置工人"抓到（放置计数代码 `CEO.exe+2BE7C` 起）：

| 偏移 | 内容 | 证据 |
|---|---|---|
| +0x1D4 | word：厂内**主管**数 | `inc word [edi+0x1D4]`（[ebx+2]==1 时） |
| +0x1D6 | word：厂内**工人**数 | `inc word [edi+0x1D6]`（[ebx+2]==0 时），实测 6→7 |
| +0x1DC 起 | 实体列表：8 字节/条 `类型word + x坐标word + y坐标word + 附加word` | 工人实体的坐标会变（走动），静态的是机器/家具 |
| +0x90 附近 | 厂名 ASCII（实测 "0002"） | dump 直接可见 |
| +0x80 / +0x84 | 两个子结构指针（+0x80 指向 12 字节步长的指针数组；+0x84 指向含 FF FF 空槽标记的数据块） | 未深挖 |
| +0x320 起 | **按类型的池计数数组**（word，索引=类型字节） | 见 2.4 |

定位方法（可复现）：`ce_set_breakpoint(厂内工人数地址, write)` → 用户放一个工人 → `ce_get_set_context()` → RDI 即厂房结构基址。
（如何先找到"工人数计数器地址"见 §3 的值扫描链。）

### 2.3 放置/携带物机制

- 携带物描述符（放置断点时的 ebx，本次 0x65C28D8）：**[ebx+2] = 携带类型字节**（0=工人，1=主管）。同一次放置内不变，多次放置间复用同一地址——它是"当前携带物"描述符，不是工人个体。
- 放置计数代码 `CEO.exe+2BE7C`：读 [esi+0B] 与 [ebx+2] 做 XOR 更新标志，再按 [ebx+2] 分路 inc 厂房计数。

### 2.4 游戏每帧运行的"池→实体分派"（重要发现）

`CEO.exe+39420` 起的代码**每帧对每个厂房执行**（未放置时也命中断点）：

```asm
movzx ecx, byte [ebx+0x4E9]          ; 类型字节（实测出现过 3）
cmp word [esi+ecx*2+0x320], 00       ; esi=厂房池结构, 该类型可用计数
jle skip                             ; 无可用 → 跳过
...
push eax(=type) / mov ecx, esi
call CEO.exe+19BB0                   ; 取实体方法: 返回 RDX=实体指针, eax=状态
test eax,eax / jne skip              ; 非 0 → 走失败分支
and byte [edi+13], 0xEF              ; 成功: 清实体标志位
```

实测样本：esi=0x1767FF8（另一个厂房的结构），类型=3，池计数=1，方法返回 RDX=0x1661D8A0。
**含义**：游戏对厂房做按类型的实体池管理，且存在每帧自动分派逻辑——这可能是"自动分配"的内置雏形，值得重点逆向 `CEO.exe+19BB0` 取出的实体去向。

### 2.5 厂房内工人数计数器（值扫描链定位的成果）

`0x1761626`（= 厂房结构+0x1D6）——每放置一个工人 +1，无论放机器上还是空地上。**这个地址是"值扫描链"的成果**，注意它属于厂房结构，不是独立全局。

## 3. 定位过程中的方法记录（复现侦查用）

1. **值扫描链**（定位厂内工人数计数器）：持主管扫 byte=1（139 万）→ 换工人 =2（657）→ 取消 =0（58）→ 再拾主管 =1（9）→ 再换工人 =2（2 个）→ 写 1 后"不拾取直接点厂房空槽放出主管"行为验证 → 实锤 `CEO.exe+4A8C24`（这是阶段 3 的成果，本任务复用了它的断点/验证手法）。
2. **未知初扫 + 放置 diff**：`ce_scan_new(type=byte, scan_type="unknown")` → 放工人 → `ce_scan_next(changed)`（157 万，噪声大）→ 换 **increased_by 1** 过滤（每放一个过滤一轮：13065 → 765 → 123 → 59 → **2**）→ 剩余即"厂内工人数"类计数器。
3. **教训**：往不同机器上放置会让"每轮 +1"的交集失效（各机器计数器不同时 +1）——**要往同一台机器连续放置**才能让它的计数器留在过滤集里。
4. **机器 x/y m/n 没有简单计数器字节**：AOB 扫 "00 01 01 02"/"00 00 03 03" 命中过杂（65/623 处），抽样 dump 像地表数据——已排除"直接搜需求值组合"这条捷径。

## 5. 候选线索（下一步优先验证）

按性价比排序：

1. **跟踪 `CEO.exe+19BB0`（池取实体方法）返回的实体（RDX）去向**——它是每帧分派的核心。做法：断点停在 call 返回处（`CEO.exe+3945A`）→ 单步跟 RDX 的写入/传递 → 找到"实体↔机器槽位"的关联写入。
2. **工人"走到机器后被识别"瞬间的写入**：拿一个已放置工人的实体对象地址（放置断点时的 RSI，本次 0x167269E0/0x16726558，两次相差 0x488，疑似实例池），对其挂 access/write 断点，等游戏把它分配/移动时抓写入代码。
3. **0x13F5xxx 簇**（阶段 3.5 值扫描轮 4 中 ~30 条值 2-5 的小字段，跨 29KB）：疑似全地图所有厂房的槽位记录数组——用"另一个厂房的机器数量不同"做差分验证。
4. **厂房结构 +0x84 子结构**（含 FF FF 空槽标记 + 21 00 等字段）：可能是机器槽位表。
