# 創業王 v1.10 全量字符串提取

> 产出日期：2026-09-15　｜　工具：`extract_strings.py`（纯静态，不附加进程、不改动游戏）
> 用途：把 v1.10 全部文本载体里的字符串抽出来，供逆向分析 / 文本替换 / 本地化参考。

**能提取，已提取。** 全部产物在 7 个分类表 + 1 个去重总表中，合计：

**最重要的两个认知**（此前文档里没有、且与直觉相反）：

1. **`CEO.exe` 里有大量真实的 Big5 繁体中文**，不是只有 ASCII。
   内含**教学文本全文**、关卡名（`教學關卡一`～`六`）、地图名（`加勒比海`/`北京市`/`北美洲`/`夏威夷群島`…）、
   UI 标签（`產品名稱`/`原始需求`/`累計需求`/`總零售利潤`/`學生人口`/`工作人口`…）、
   报错串（`的參數數量不對`/`機器入口座標錯誤`）、字体名（`細明體`）、游戏名（`創業王`）。共 92 条。
   分布：**`.rdata` 73 条**（RVA ≈ `0xA2000`–`0xB0C0C`，含全部教学文本与 UI 标签）、
   **`.data` 18 条**（RVA ≈ `0xB1000`+，关卡名/地图名/`細明體`，运行时会组装成表）、
   `.text` 1 条（是假阳性）。
2. **界面主语言是繁体中文，编码是 Big5（大五碼），不是 UTF-8/Unicode。**
   exe 里的 UTF-16LE 只有 34 条，且**全部来自 Steam 包装层的 CRT 资源**（月份/星期/`800 x 600`/`Windows原設定`），
   **没有一条是游戏本体文本**。→ 做文本替换/本地化时改 Big5 字节，不要动 UTF-16。

> ⚠️ **地址用法提醒**：本目录 TSV 里的地址是 `CEO.exe+RVA`（模块内偏移），**不是** VA。
> 换算 `VA = 0x400000 + RVA`（如 `CEO.exe+A2858` = VA `0x4A2858`）。
> 详见 AGENTS.md §2.1 与本文坑 #18。

## 3. 方法（比结论更重要）

### 3.1 核心难题：二进制里扫 Big5 会产生海量假阳性

任意两个字节只要满足「首字节 0x81–0xFE + 次字节 0x40–0x7E/0xA1–0xFE」就能按 Big5 解码。
x86 机器码里这种组合极多，于是代码段会被解出成片的「假中文」，例如：

```
CEO.exe+5E9   嬁襟昍孢        ← 机码巧合，不是文本
CEO.exe+623   襟昍昍昍昍昍    ← 代码填充
```

**直接扫 exe 会得到 3,662 条「Big5 形态段」，其中绝大多数是垃圾**，必须过滤。

### 3.2 解法：用「游戏自身用字集」做两阶段自举过滤

游戏文本有一个强特征：**用字范围稳定**（同一款游戏不会用生僻字）。因此：

```
阶段1  从**确定可信**的来源（data CSV + stage + APKG 名）建立「可信用字集」（实测 1,300 字）
阶段2  扫 exe 的 Big5 形态段，只保留「落在可信用字集内的字符占比 ≥ 阈值」的段
阶段3  用阶段2 的高置信结果（占比 ≥ 0.99）**反哺扩充**用字集，再跑一遍（自举）
```

效果对比（同一份 exe）：

| 判据 | 保留条数 | 内容 |
|---|---|---|
| 裸扫（仅形态判断） | 3,662 | 绝大多数是乱码 |
| + 用字比 ≥ 0.99 | 54 | **全部为真文本** |
| + 用字比 ≥ 0.85（自举后） | 88 | 真文本 |
| + 候选档（见下） | 92 | +3 真串 +1 噪声 |

被过滤掉的典型假阳性：`嬁襟昍孢`、`襟昍昍昍`、`葦牧金休`（用字比 0.75，来自 `0x18 0xFE` 之类的指令字节）。

### 3.3 为什么分「高 / 候选」两档而不是单一阈值

调高阈值会**误杀真串**，调低会**放进噪声**，实测都有实例：

| 字符串 | 用字比 | 真相 |
|---|---|---|
| `方向數不符` | 0.80 | 真（错误提示） |
| `地圖尺寸請調整為` | 0.75 | 真（错误提示，右侧接空格所以 run 在此截断） |
| `語法錯誤` | 0.50 | 真（脚本解释器报错） |
| `贊濟摛` | 0.67 | **假**（代码巧合） |

所以采用两档，**不丢真串、也不掩盖噪声**：

- **高**：用字比 ≥ 0.85 → 直接收录
- **候选**：用字比 ∈ [0.5, 0.85) **且至少一侧紧邻 `0x00`** → 收录但标注
  （`.rdata` 字符串表里的串一定是 null 结尾；代码里的巧合字节极少两侧带 null。这条规则把噪声挡在外面，同时救回 `語法錯誤`。）

TSV 里保留 `用字比` 原始数值，可按需再筛。

### 3.4 APKG 格式（本次反推，可直接复用）

```
偏移 0   : 'APKG'                       magic
偏移 4   : u32  索引起始偏移             （= 文件长度 - 文件数×40）
偏移 8   : u32  文件数
偏移 12  : 各文件数据...
索引区   : 每条 40 字节 = 文件名(32字节, Big5, \0 填充) + 偏移(u32) + 大小(u32)
```

验证（`DATA.APKG`）：`文件数=26`，`26×40=1040`，`文件长 355,954 - 354,914 = 1040` ✓；
第 0 条 = `AIInfo.csv`, off=12, size=557 ✓；第 1 条 = `AI_style.csv`, off=569, size=2459 ✓（与 `_MANIFEST.tsv` 完全一致）。

> 注意：`STAGE.APKG`(`21×40=840`)、`MAPS.APKG`(`126×40=5040`)、`FACE.APKG`(`276×40=11040`) 均满足同一公式。

### 3.5 `.stg` 格式

```
重复: u32 段号 + u32 压缩长度 + zlib 流
```
解压后含 Big5 地名/公司名，如 `創業王企業`、`單菱商社`、`微硬公司`、`敗耳企業`、`加樂福企業`、`矽礦場`、`鋁礦場`。

  这是**文件偏移**，不是 RVA，不要直接拿去 CE 用。

## 6. 坑点（本次新增，已同步进 `v1.10移植实战记录.md` §3）

- **坑 #15**：二进制里裸扫 Big5 = 海量假阳性，**必须**用用字集过滤（见 §3.1/§3.2）。
- **坑 #16**：TSV 写出前必须转义制表符/换行——exe 的 ASCII 串**允许含 `\t`**（实测 **103 条**，如
  `}\tG;=`、`T:\tR`），不转义会把列冲乱（曾导致总表出现空「类型」列与 `J`、`G;=`、`%d` 这类错位值，
  排查时一度误判为编码问题）。
- **坑 #17**：`.stg` 的 zlib **不可整文件 `zlib.decompress`**（多段拼接，报 `incorrect header check`），
  必须按 `u32 段号 + u32 长度` 逐段解。
- **坑 #18**（最隐蔽，本次差点交付错地址）：**文件偏移 ≠ RVA**。PE 节的 `PointerToRawData` **不等于**
  `VirtualAddress`（本 exe：`.text` RawPtr `0x400` / VirtAddr `0x1000`；`.rdata` `0xA0600` / `0xA2000`）。
  扫文件拿到的是**文件偏移**，直接当 RVA/VA 写进产物会全错（本次 92 条中文地址全部偏移了 `0xC00`～`0x1A00`）。
  必须按节表做 `RVA = VirtAddr + (fo - RawPtr)` 换算，并**用独立来源交叉验证**——
  本次用 IDA 导出的 `03_分析数据\strings_all.json`（VA 记法）比对，**696/696 条完全一致**才确认无误。
